## Basic Docker Commands
### Run an interactive container
To run a docker image and make it interactive (with a terminal):
```bash
docker run -it <docker-image>
```
Example:
```bash
docker run -it python:3.13.11-slim
```
### Open a bash shell in a container
To start a container and open a bash shell inside it:
```bash
docker run -it --entrypoint=bash <docker-image>
```
Example:
```bash
docker run -it --entrypoint=bash python:3.13.11-slim
```
---
## Managing Containers
### List containers
To see all containers we have created so far:
```bash
docker ps -a
```
### List only container IDs
To see only the IDs of the containers:
```bash
docker ps -aq
```
### Remove all containers
To remove all previous containers at once:
```bash
docker rm $(docker ps -aq)
```
---
## Understanding Container Statelessness
Containers are stateless by default. This means:
- Any files created inside a container are temporary
- When you exit and re-enter a container, previous changes are lost
### Example of stateless behavior
If you create a file inside a container:
```bash
echo 123 > file
```
Then exit the container and re-enter it, the file will not be there. The container starts fresh each time.

## Preserving Data: Volume Mapping
### The Problem
How do we preserve state in docker? How do we keep files and data persistent?
### The Solution: Volume Mapping
Volume mapping allows you to share files between your host machine and the container. Files on your host become available inside the container.
### How Volume Mapping Works
We can map a folder on our host machine to a folder inside the container. This makes the files accessible from both locations.
### The Volume Mapping Command
```bash
docker run -it --entrypoint=bash -v ${pwd}/test:/app/test python:3.13.11-slim
```
### Breaking Down the Command
| Part | Explanation |
|------|-------------|
| `docker run -it` | Run interactively with a terminal |
| `--entrypoint=bash` | Open a bash shell when the container starts |
| `-v` | The volume flag (tells docker to mount a folder) |
| `${pwd}/test:/app/test` | The mapping: host folder : container folder |
| `python:3.13.11-slim` | The docker image to use |
### Understanding the Mapping
`${pwd}/test:/app/test` means:
- Left side (`${pwd}/test`): The folder on your host machine
- Right side (`/app/test`): The folder inside the container
- The colon `:` separates the two paths
### Practical Example
1. On your host machine, create three text files in a folder called `test`
2. Write a python script to read the content of those text files
3. Instead of running the script on your host machine, run it from inside the container
4. Use volume mapping to make the `test` folder available inside the container
5. The container can now access and read those files
---
## Summary
- Docker images are templates (name + tag)
- Containers are stateless by default
- Volume mapping (`-v`) preserves data by sharing files between host and container
- Use `docker run -it --entrypoint=bash -v <host-path>:<container-path> <image>` to mount volumes
