since we had two containers running in sequential to each other, Now we want to run them in the same time together 
```bash 
docker run -it --rm `
  -e POSTGRES_USER="root" `
  -e POSTGRES_PASSWORD="root" `
  -e POSTGRES_DB="ny_taxi" `
  -v ny_taxi_postgres_data:/var/lib/postgresql `
  -p 5432:5432 `
  --network=pg-network `
  name pgdatabase `
  postgres:18
```

```bash
  docker run -it `
  -e PGADMIN_DEFAULT_EMAIL="admin@admin.com" `
  -e PGADMIN_DEFAULT_PASSWORD="root" `
  -v pgadmin_data:/var/lib/pgadmin `
  -p 8085:80 `
  --network=pg-network `
  --name pgadmin `
  dpage/pgadmin4
```

to do so we will use docker compose 
so we create a file called docker-compose.ymal
and this file will describe all the docker images we want to run 
so we have **pddatabase** container and we have **pdadmin** container 
and we want to run them together in the same network 
to do so I asked gemini to create the docker-compose, and this is the result:
```python
version: '3.8'

services:
  pgdatabase:
    image: postgres:18
    container_name: pgdatabase
    environment:
      - POSTGRES_USER=root
      - POSTGRES_PASSWORD=root
      - POSTGRES_DB=ny_taxi
    ports:
      - "5432:5432"
    volumes:
      - ny_taxi_postgres_data:/var/lib/postgresql/data
    networks:
      - pg-network

  pgadmin:
    image: dpage/pgadmin4
    container_name: pgadmin
    environment:
      - PGADMIN_DEFAULT_EMAIL=admin@admin.com
      - PGADMIN_DEFAULT_PASSWORD=root
    ports:
      - "8085:80"
    volumes:
      - pgadmin_data:/var/lib/pgadmin
    networks:
      - pg-network

volumes:
  ny_taxi_postgres_data:
  pgadmin_data:

networks:
  pg-network:
    driver: bridge
```

Note: we don't need networks because everything on docker compose run on the same network, so we can delete the networks section in the docker-compose

Now to run the compose, we simply use:
```bash
docker-compose up
```
but we git this error:
```
Error response from daemon: Conflict. The container name "/pgadmin" is already in use by container "43db9e88c52c06a781c9b1cd009be776e299fe248218d5f6dcafcffe69ce50a6". You have to remove (or rename) that container to be able to reuse that name.
```
so the simplest solution is just to remove all prevouse containers we had 
```bash 
docker rm $(docker pa -aq)
```
Now we reRun our compose 
but we will remove the containers name so docker compose can select what ever name it want 
But now we get an error related to postgres:
```
The error occurs because **PostgreSQL 18** modified its volume mount structure and strict checking. When mounting a named volume to `/var/lib/postgresql/data`, the container detects existing or unexpected data files and immediately exits with `code 1`.
```
and the fix is to change the volume path in our docker compose file 
```
from /var/lib/postgresql/Data
to   /var/lib/postgresql
```
So now it worked and we get that:
- **Database Initialization**
- **Postgres is Active**
- **pgAdmin is Active**
and we will be able to access our database from pgAdmin interface and connect to it .

But we will see the Tables are empty which means that the data is empty 
so we need to run the ingestion script

if we created a new terminal and run:
```bash 
docker network ls
```
we will see a new network called
```
237284248b27   trying-docker_default   bridge    local
```
which is the created network by our docker-compose, and it's called trying-docker because this our project folder name and because we didn't specify any name for it 


so to run our script on the docker compose network we will use this command 
```bash
  docker run -it --rm `
--network=trying-docker_default `
  taxi_ingest:v001 `
  --pg-user=root `
  --pg-pass=root `
  --pg-host=pgdatabase `
  --pg-port=5432 `
  --pg-db=ny_taxi `
  --target-table=yellow_taxi_trips
```
we just changed the network name to  trying-docker_default
so now it will start ingesting the data 
so now if go back to pg-admin and refresh the database we will see how the taxi data was ingested
